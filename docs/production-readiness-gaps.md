The pre-implementation baseline is [prior-phases-baseline.json](../evidence/phase5/prior-phases-baseline.json): 550 project files, including 391 Phase 1–4 evidence files (54 / 73 / 77 / 187); SHA-256 `043b6c7a7ae68515b7c17379619a090d24a01d361f5ba72816d89da97b93f9e2`. Completed phase reports and archives remain historical records.

Inspection covered the Phase 2/3/4 completion reports, prior verification outcomes and evidence bindings, architecture/monitoring/alerting/notification/oracle/evidence/security/testing documentation, package/lock/configuration, CLI dispatch, reader/transport lifecycle, assurance/risk boundaries, SQLite migrations 1–4, outbox, retention and verification/fixture output paths. This register describes the starting state, not an assertion that remediation has passed. Final dispositions are recorded in the Phase 5 report and release-readiness assessment.

## Starting assumptions

- Actual local runtime: **Node v24.14.1, SQLite 3.51.2, Windows**. Package compatibility currently says Node >=22.18.0; this is broader than the verified production runtime. Application version is **0.1.0**; `git rev-parse --verify HEAD` has no revision to report.
- One fixed public demonstration position, chain **1672**, fixed RPC and hosted MCP. Both access paths share an upstream. No environmental endpoint or chain override exists. Only three optional notification credential variables are read, and only for enabled adapters.
- One worker owns one local SQLite database. Existing WAL/FULL/foreign-key/transaction/checksum checks are useful but do not validate a production filesystem, supervisor, backup or shutdown deadline.
- Recovery arithmetic remains indicative. Oracle assurance is **UNVERIFIED**, freshness is **UNKNOWN**, independent economic validation is unavailable, and **actionable: false** is mandatory.
- Phase 4 verification passed 22/22 commands, 562/562 unit tests and 2/2 live integration tests. Those are bounded local results, not production soak evidence.

## Implementation direction

Use a single dedicated Node worker with existing read-only RPC/MCP access and durable SQLite outbox. Keep process supervision outside the application and diagnostics as local CLI commands. Use SQLite online backup into newly created local directories, then validate an isolated restoration. Production runtime/configuration gates and bounded resources fail clearly; they do not promote oracle assurance. All external notification verification uses mocked HTTP. Production deployment and monitoring require later separate approval.
